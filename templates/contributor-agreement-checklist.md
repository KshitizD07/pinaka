# Pinaka Contributor & Project Onboarding Agreement Checklist

> Use this checklist when onboarding a friend's project, external team, or hackathon (SIH) entry into the Pinaka Studio portfolio.

- [ ] GitHub Repository URL: _______________________
- [ ] Target Track: [ ] Flagship  [ ] Incubating (Hackathon/SIH)  [ ] Community Showcase  [ ] Research Labs

## 2. IP & Ownership Guarantees
- [ ] **Creator Retains IP**: The creator/builder retains 100% intellectual property ownership of their source code, designs, and domain assets unless explicitly contracted under a formal spin-out equity agreement.
- [ ] **Showcase Rights Granted**: Creator grants Pinaka Studios permission to list, showcase, link, and feature the project and metrics on the Pinaka web portal and community channels.
- [ ] **Licensing Clarity**: Repository includes a clear open-source or proprietary LICENSE file (e.g., MIT, Apache 2.0, or All Rights Reserved).

## 3. Engineering & Security Commitments
- [ ] **No Exposed Secrets**: Zero hardcoded API keys, JWT secrets, database credentials, or private keys committed in history.
- [ ] **Adherence to Pinaka Baseline**: Conforms to `01-engineering-handbook.md` and basic security protocols in `06-security-and-secrets.md`.
- [ ] **Live Demo Standard**: Project maintains a working live demo URL or reproducible simulation harness. Broken demos must be remediated within 14 days or moved to the "Archived" status.

## 4. Maintenance & Inactivity Clause
- [ ] **Named Maintainer**: Every project has a designated point of contact responsible for security patches and major bug fixes.
- [ ] **Graceful Archival**: If a project remains unmaintained for >60 days without response, Pinaka reserves the right to mark the project as `archived` or `open-source maintenance wanted` on the showcase hub to preserve studio brand integrity.
